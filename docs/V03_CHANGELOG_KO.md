# v0.3 변경 이력 · 개발자와 감독관을 위한 검증 안내

## 실제 작성된 기능
- 상태 분리: 대기 → 시험 전 기준 수집 → 수동 시험 시작 → 시험 중 감시 → 종료/저장
- 기준 수집 90초 권장, 실제 와이파이 새 검색 결과 2회 권장. 이 조건이 부족해도 확인창을 통해 시험 시작 허용
- 같은 Wi-Fi 접속점(BSSID)이 서로 다른 **갱신된** 검색에서 두 번 이상 관측되고 '일반 가전·설비'로 추정될 때 자동 알림 제외
- 자동 제외는 다른 목록으로 접는 것만 의미. 해당 신호의 저장/탐지 지속, 수동 관심 지정으로 우선 확인 복귀
- 시험 중 신규 식별자 관측 및 관측 구간 수, 수동 검토, 개별 신호 근접 변화 보기
- SQLite 스키마 v3, v1·v2 업그레이드 경로, CSV에 추가 상태 기록
- 기존 v0.2 자동 4분류·수동 분류·로컬 CSV 기록 유지

## 정책 상세
1. 기존 접속점 자동 제외는 MAC/BSSID 자체가 진짜 고정 설비임을 인증한 것이 아니다. 이를 이름 기반 분류 + 반복 갱신으로 추정할 뿐이다.
2. 이름 없는 접속점이나 스마트폰/카메라/착용형 장치로 추정된 신호는 자동 제외하지 않는다.
3. 기존 신호라도 수동 관심 지정할 수 있다.
4. RSSI는 같은 송신원/수신 환경 조건에서 상대적인 변화만 제공하며 좌석 위치나 거리(m) 판정은 하지 않는다.
5. BLE 재관측은 서로 다른 10초 시간 구간 3개 이상을 의미하며 실제 통신 패킷의 주기 분석이 아니다.
6. Wi-Fi 재관측은 업데이트된 AP 목록에 서로 다른 갱신 결과 2회 이상 나타난 경우다. AP가 정기적으로 보내는 비콘과 카메라 영상 송신을 구별하지 않는다.
7. 재검색 빈도와 AP 측정 시각의 차이는 시스템 정책에 따르므로 '즉각 실시간 탐지'라고 표시하지 않는다.

## 소스 수준 확인
- 순수 Kotlin 정책 테스트: AP 2회 관측/1회 관측, 의심 기기·휴대전화 제외, 수동 관심 지정, 반복 BLE, 감독관 확인 완료
- XML 리소스 파싱 / MainActivity에서 참조하는 레이아웃 ID 대조
- Android SDK와 실측 장비가 없는 환경에서 APK 빌드 및 실제 단말 시험은 수행하지 못함

- [ ] 정상 갱신된 와이파이 2회 미만 시 경고 표시
- [ ] 알려진 고정 공유기 2회 이상 관측 후 시험 시작 시 '기존 AP 제외' 목록에 나타나는지

- [ ] '관심 신호로 지정' 후 우선 확인에 다시 나타나는지

- [ ] Wi-Fi 검색 제한 또는 갱신 안 됨 상태에서 이전 결과가 신규 관측으로 중복 추가되지 않는지
