# 시험장 무선 신호 관측기 / ExamSignalWatch

**Android · Kotlin · 오프라인 · 완전 무료 · 실험용 v0.3.0**

시험 감독관을 위한 무선 신호 *관측·기록* 시제품입니다. Android가 제공하는 **BLE 광고 신호**와 **Wi-Fi 접속점(AP) 검색 결과**를 수집합니다. 앱은 카메라의 실제 영상 송출, Wi-Fi 클라이언트 목록, 부정행위 여부, 송신원의 정확한 위치를 확인하지 않습니다.

> **개발 상태:** v0.2 기반으로 v0.3 기능을 작성했고 순수 Kotlin 정책 로직 테스트 및 XML 정적 검사를 완료했습니다. 현재 작업 환경에서는 Android SDK가 없어 v0.3 전체 APK 빌드·실기기 실행은 검증하지 못했습니다. GitHub Actions에서 APK 빌드를 실행하고 현장 검증을 완료한 뒤 사용하세요. 국가시험 공식 탐지 장비가 아닙니다.

## v0.3 추가된 기능

1. **시험 전 기준 신호 수집**: 앱의 '시험 전 기준 신호 수집'을 눌러 기준값 수집. 90초/실제 새 Wi-Fi 검색 결과 2회 이상 권장.
2. **명시적인 시험 시작**: 감독관이 별도 '시험 시작' 버튼을 누른 시점부터 신규 신호를 판정. 기준 측정 도중에는 자동으로 시험 시작 상태로 전환되지 않음.
3. **기존 Wi-Fi AP 자동 접기**: 시험 전 동일 BSSID가 서로 다른 신선한 검색 결과에서 2회 이상 관측되고 이름 기반 일반 가전·설비로 추정된 AP만 기본 경고 목록에서 접음. 검색·저장은 계속됨. 숨김 AP, 스마트폰 핫스팟·카메라 의심 이름은 자동 접지 않음.
4. **시험 중 신규·반복 신호 우선 확인**: 시험 시작 후 새로 등장한 신호와 여러 시간 구간에서 재관측된 일부 신호를 우선 확인 목록에 배치. BLE는 10초 구간 3개 이상, 와이파이는 서로 다른 새 검색 결과 2회 이상으로 '반복 관측' 참고값 표시. 실제 패킷 송신 주기나 촬영을 판별하지는 않음.
5. **관심 신호 지정 / 자동 제외 해제**: 개별 행에서 직접 '관심 신호로 지정' 버튼을 눌러 우선 확인에 복귀 가능.
6. **근접 신호 검사**: 선택한 신호의 최근 RSSI 변화 추세 및 마지막 관측 시간 표시. 새 측정값을 기다리며 화면이 열려 있는 동안에만 기록. 정확한 거리·방향 측정 아님.
7. **필터**: 우선 확인 / 시험 중 신규 / 반복 관측 / 기존 AP 제외 / 전체 / 기기 종류별.
8. **로컬 기록/CSV**: 시험 시작 시각, 시험 전 성공한 새 Wi-Fi 관측 횟수, 자동 제외·수동 관심 지정, 시험 중 관측 구간 수 추가. SQLite v2→v3 마이그레이션으로 기존 기록 보존.

## 탐지의 한계 (출시 전에 반드시 읽기)

- 기본 Android API는 주변 Wi-Fi AP 검색에만 접근합니다. 공유기에 연결된 카메라 자체를 자동 검출하거나, 타 기기들의 영상 송신을 캡처할 수 없습니다.
- v0.3의 USB RTL-SDR 상태 표시는 **실제 RF 수신 기능이 아닙니다**. 2.4GHz Wi-Fi도 RTL-SDR Blog V4로 직접 수신할 수 없습니다.
- BLE를 송출하지 않는 블루투스 기기, 수신 전용 이어폰, 전원이 꺼진 장비, 저장형 카메라는 발견하지 못할 수 있습니다.
- 기준 시점에 기존에 숨겨 놓은 기기가 있을 수 있으므로 기존 AP 자동 접기는 **안전 판정이 아닌 알림 정리** 기능입니다.
- 신호 세기, 검색 가능한 장치 이름, BSSID 모두 장치 정체와 학생 위치를 증명하지 않습니다. 실기기 실측 검증 전 시험 감독용으로 의존하지 마세요.
- 와이파이 검색은 Android 버전/기기/위치 서비스/사용자 설정에 의해 제한됩니다. `ScanResult.timestamp`로 실제 갱신된 AP만 새 관측으로 처리하도록 구현했으나 제조사별 동작은 검증 필요합니다.
- 화면을 벗어나면 탐지가 중단되며 세션이 종료됩니다. 백그라운드 감시 미지원.

## 빌드

- Android Studio: JDK 17, Android SDK Platform 35, Gradle 8.11.1 / Android Gradle Plugin 8.9.2 / Kotlin 2.1.10.
- 프로젝트 폴더에서 `gradle :app:assembleDebug`.
- 또는 GitHub Actions: `.github/workflows/android-debug.yml`이 `setup-android@v4`를 사용해 Gradle을 설치하고 디버그 APK를 빌드합니다. GitHub → Actions → Android Debug APK → 성공한 작업의 Artifacts 다운로드.
- 실제 APK 빌드와 스마트폰 실측 테스트가 완료되지 않았으므로 빌드 실패 시 Actions 상세 로그를 확인하세요.

## 기본 시험 단계

1. 스마트폰 블루투스와 와이파이를 켜고 필수 권한을 허용.
2. **시험 전 기준 신호 수집**을 누르고 90초 이상, 갱신된 Wi-Fi 결과 2회 이상을 권장.
3. 감독관이 실제 시험 시작 시 **시험 시작**을 누름. 준비가 부족할 경우 경고 메시지에서 추가 수집 선택 가능.
4. **우선 확인**에서 신규·반복 신호 확인. **기존 AP 제외**에서 접힌 신호 확인/관심 지정 가능.
5. 의심 신호 클릭 후 **근접 신호 검사**에서 RSSI 변화를 참고. Wi-Fi는 새 검색 간격 때문에 실시간 반응을 보장하지 않음.
6. **검사 종료 및 기록 저장**, **기록·내보내기**에서 CSV 저장.

## 파일 구조

- `app/src/main/java/org/openexam/signalwatch/SignalScanner.kt` — 실제 BLE·Wi-Fi 신호 수집, 신선한 와이파이 검색 결과 확인
- `.../ExamSignalPolicy.kt` — Wi-Fi AP 자동 접기·재관측 판단·우선 확인 규칙 (순수 Kotlin)
- `.../MainActivity.kt` — 감독관 UI·상태 전환·RSSI 근접 검사·분류 수정
- `.../SignalStore.kt` — SQLite 데이터 저장 및 CSV
- `.../DeviceClassifier.kt` — 이름 기반 보수적 4분류 추정
- `app/src/main/assets/guide_ko.txt` — 오프라인 상세 사용설명서
- `docs/V03_CHANGELOG_KO.md` — 정책, 검증, 아직 검증하지 못한 항목

## 외부 코드 및 라이선스

프로젝트의 새 소스는 Android 표준 API를 이용해 독립적으로 작성했습니다. 기존 RF Sentinel / NoPeek / Spectrum 프로젝트는 구현 참고자료로만 사용했으며 외부 구현 소스는 복사하지 않았습니다. 이 소스는 `LICENSE`의 MIT 조건을 따릅니다. GPL 소스를 향후 통합하는 경우 GPL 원작자 고지와 라이선스 의무를 별도로 재검토해야 합니다.

인터넷 사용 권한, 사용자 계정, 광고, 통신 내용 감청 기능은 없습니다. 센서 관측 정보와 기기 이름은 로컬에 저장합니다. MAC/BSSID 원문 대신 세션별로 바뀌는 해시 ID를 저장합니다.
